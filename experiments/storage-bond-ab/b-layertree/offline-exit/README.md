# FROST carrier: service-dead frozen full-split recovery

**Experimental regression, disposable Bitcoin Core regtest only.**
Not a permissionless covenant, not Filecoin proof adjudication, and not
two separately signed unilateral carrier exits.

## Question

Can an ordinary broadcaster recover a 100,000-satoshi FROST P2TR carrier
when the 2-of-3 signer process, the fee sponsor's wallet and the Sapio
oracle are unavailable, provided everyone signed a **complete exact
60k/40k full-split exit ahead of time**, including the fee input?

## Two execution phases

Phase 1 runs **real** `frost-secp256k1-tr = 3.0.0` and Bitcoin Core.
The preparation binary creates three carrier generations, separately
pre-signs one full-split exit for each generation, signs two carrier
refresh transactions, and broadcasts only the refreshes. Bitcoin Core
confirms the two refreshes. Each frozen exit spends its generation's
full carrier and independent sponsor input and pays 60,000 sats to
Alice, 40,000 to Bob and precisely 3,000 sats in BTC miner fees
**from the sponsor**, not from either entitlement.

It writes a private, exclusive frozen JSON export plus SHA-256 seal.
No FROST secret shares or nonce material are serialized.
Then the signer OS process exits. The shell unloads sponsor,
Alice and Bob wallets from Bitcoin Core; only the unrelated miner
wallet remains to generate regtest blocks. No Sapio or signing process
is called by the second phase.

Phase 2 invokes `relay_current.mjs` through Node alone. It independently
checks SHA-256 integrity against the pre-shutdown captured digest, actual
SegWit wtxids, exact signed inputs, original parent scripts/amounts,
60k/40k outputs, 3,000-sat already-funded sponsor fees and ancestry.
Bitcoin Core rejects exits frozen against obsolete generations 0 and 1,
and accepts the current generation 2 full-split. The worker publishes
unchanged signed bytes, mines six confirmations, and verifies both
beneficiary outputs are unspent.

The CI runs this *twice* with separate fresh Bitcoin histories:
the first recovery worker is labeled Alice and the second Bob.
Both publish the same *form* of pre-signed **joint** full-split exit,
rather than each using a separate owner-specific claim. No private
owner key is necessary to publish an already signed Bitcoin transaction:
any third-party relay could do it too.

## Run

Use only disposable `bitcoind` and `bitcoin-cli`, plus Rust, Node 22 and
this branch. Never use a production Bitcoin datadir or private keys.

```bash
BITCOIND_EXEC=/absolute/path/to/bitcoind \
BITCOIN_CLI_EXEC=/absolute/path/to/bitcoin-cli \
BSB_OFFLINE_RECEIPT_DIR=/private/new-offline-proof \
bash experiments/storage-bond-ab/b-layertree/offline-exit/run_regtest.sh
```

CI: `.github/workflows/layertree-frost-offline-exit.yml`.

## Attacker and failure boundaries

- **Proven only if the CI passes:** each broadcaster uses a previously
  signed full split, with zero fresh FROST signatures and zero fresh
  sponsor or holder-wallet signatures during recovery.
- **Cannot prove:** that Alice can independently withdraw only her
  60,000 sats from the pre-split carrier; the exit is a shared full-split
  transaction that Alice or Bob or a third party may relay.
- **Cannot protect against malicious quorum:** two active FROST signers
  can still sign a competing, Bitcoin-valid P2TR keypath spend
  redirecting all principal. The preparation phase explicitly checks
  this counterexample and never broadcasts that alternative.
- **Refresh caveat:** a previously signed exit only remains valid while
  its Bitcoin input outpoint is current. A refresh performed without
  replacement pre-signatures can leave owners stranded. Three
  generated exit sets test bounded refresh continuity, not indefinite
  refresh safety.
- **No MID covenant:** this script is the same unrestricted FROST
  keypath from the earlier funded regtest. Native Bitcoin does not
  enforce the OP_RETURN commitment or Sapio MID oracle transitions.
- **No production availability:** the frozen export and separate hash
  are generated by one disposable trusted-dealer process, not a
  distributed actor that durably delivers witnesses to holders.
  The replay-resistant, rollback-resistant, per-owner evidence
  distribution protocol is still missing.

## Next practical research

Test externally carried, per-holder frozen independent recovery packages
and separate sponsor funding when signers are gone. Prove the fallback
against an unavailable oracle AND a malicious active two-share quorum
as distinct adversaries. Until Bitcoin rejects an unauthorized
threshold signed alternative, classify this as a **federated bond
with presigned service-outage recovery**, not a permissionless slash.
